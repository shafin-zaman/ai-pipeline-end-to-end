# Skill: Push to GitHub & Open PR (Stage 4)

## What this skill does
Initialises (or reuses) a Git repository for the output, creates a new branch named after the Jira story, commits all output files with a meaningful message, pushes to GitHub, and opens a Pull Request with the Jira story key in the title.

## Inputs required
- `issue_key` — e.g. `AI-42`
- `summary` — the Jira story summary (used in branch name and PR title)
- `GITHUB_TOKEN`, `GITHUB_REPO` from environment

## Outputs
- A pushed branch: `feature/AI-42-<slug>`
- An open GitHub Pull Request with `AI-42` in the title
- `pr_url` — the URL of the created PR (passed to Stage 5)

---

## Step-by-step instructions

### Step 1 — Prepare branch name
Slugify the Jira summary:
- Lowercase
- Replace spaces and special characters with hyphens
- Truncate to 40 characters
- Result: `feature/AI-42-simple-todo-app`

### Step 2 — Initialise git in the output directory
```bash
cd output/{issue_key}

# If not already a git repo:
git init
git remote add origin https://{GITHUB_TOKEN}@github.com/{GITHUB_REPO}.git

# Create and switch to the feature branch:
git checkout -b feature/{issue_key}-{slug}
```

### Step 3 — Stage all output files
```bash
# Stage app files
git add index.html
# Stage any additional files (CSS, JS, package.json, test files, etc.)
git add -A

# Do NOT stage:
# - node_modules/ (add to .gitignore first)
# - .env files
# - Any file containing API keys
```

Create a `.gitignore` before staging if it doesn't exist:
```
node_modules/
.env
*.log
```

### Step 4 — Write a meaningful commit message
Format:
```
feat(AI-42): build {short description from requirements}

- Implements all {N} acceptance criteria from requirements.md
- Tech stack: {what was used}
- Tests: all {N} passing (see test-results.txt)

Jira: {issue_key}
```

Commit:
```bash
git commit -m "$(cat <<'EOF'
feat({issue_key}): build {short_description}

- Implements all {N} acceptance criteria from requirements.md
- Tech stack: {stack}
- Tests: all passing

Jira: {issue_key}
EOF
)"
```

### Step 5 — Push the branch
```bash
git push -u origin feature/{issue_key}-{slug}
```

### Step 6 — Open a Pull Request
Use the GitHub CLI:
```bash
gh pr create \
  --title "[{issue_key}] {summary}" \
  --body "$(cat <<'EOF'
## What this PR does
Auto-generated by the AI pipeline for Jira story {issue_key}.

**Requirements:** See requirements.md attachment on Jira story.
**Deployment:** Will be auto-deployed to Vercel from this branch.

## Acceptance criteria
{paste acceptance criteria list here}

## Test results
All unit tests passing. See `test-results.txt`.

## How to review
1. Check the deployed Vercel URL (posted as a comment once available)
2. QA report will be emailed to {QA_REPORT_EMAIL}

🤖 Generated by the Zero Human Touch Pipeline
EOF
)" \
  --head feature/{issue_key}-{slug} \
  --base main
```

Capture the PR URL from stdout.

### Step 7 — Return results
```python
{"branch": "feature/AI-42-slug", "pr_url": "https://github.com/..."}
```

---

## Error handling
- If `git push` fails due to remote conflict: append a timestamp to branch name and retry once
- If `gh pr create` fails: log the error, continue — the PR is not required for deploy
- If GitHub token is invalid: raise `PipelineError("GitHub authentication failed")`

## Principle alignment
- **Principle 3 (Tools):** Uses `gh` CLI as the agent's hands for GitHub operations
- **Principle 4 (Workflows):** Commit message format and branch naming are standardised conventions
